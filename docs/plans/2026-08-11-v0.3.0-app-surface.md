# v0.3.0 Application Surface Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

Date: 2026-08-11. Status: draft.

**Goal:** Close the gaps that stop someone building a wallet or mini app on `nimiq-go`: importing an existing account, sending without boilerplate, cashlinks, and vesting payloads.

**Architecture:** Everything offline stays in the root package or `signer`; anything needing a node goes in `rpc`. Parsing mirrors the existing `ParseHTLCCreation` idiom — `decoder` from `serialize.go`, `d.end()` to reject trailing bytes, errors prefixed `nimiq:`. No new module dependencies: `golang.org/x/crypto` (already required) covers PBKDF2 and scrypt; the BIP39 wordlist ships as an embedded file.

**Tech Stack:** Go 1.25, `golang.org/x/crypto/pbkdf2`, `crypto/ed25519`, `go:embed`.

Order matters: Task 1 is the one users are blocked on. Tasks 3–5 are independent of each other.

### Task 1: Raw RPC escape hatch

Instead of wrapping the ~180 albatross methods, export the existing private call.

**Files:**
- Modify: `rpc/client.go`
- Modify: `README.md` (one snippet under the RPC section)

**Steps:**

```go
// Call issues a raw JSON-RPC request for methods this SDK does not wrap,
// with the client's retries, timeouts, and endpoint failover applied.
// ponytail: escape hatch instead of wrapping every albatross method.
func (c *Client) Call(ctx context.Context, method string, params []any, out any) error {
	return c.call(ctx, method, params, out)
}
```

Test: one `httptest` case asserting the method name reaches the server and `out` is populated. Promote a method to a typed wrapper only after two real users ask.

### Task 2: Mnemonic import/export (`signer`)

The blocking gap. Today a key can be generated and encrypted but an existing 24-word Nimiq backup cannot be imported, so no app can offer "restore your wallet".

**Files:**
- Create: `signer/mnemonic.go`, `signer/mnemonic_test.go`, `signer/wordlist_english.txt`
- Modify: `signer/privatekey.go` (only if a constructor from a 32-byte seed is missing)

**Spec** (from `core-js/src/main/generic/utils/mnemonic/MnemonicUtils.js`):

- Wordlist: standard BIP39 English, 2048 words, embedded with `go:embed`.
- Checksum: SHA-256 of entropy, first `ENT/32` bits. Nimiq also recognises a deprecated **legacy** type using CRC-8 over the same bits; a phrase valid under both is `MnemonicUnknown` and must not be silently guessed.
- Seed: `pbkdf2(mnemonicNFKD, "mnemonic"+password, 2048, 64, sha512)`.
- Master key: SLIP-0010 ed25519 — `HMAC-SHA512(key: "ed25519 seed", data: seed)`, left 32 bytes = key, right 32 = chain code. Hardened derivation only.
- Path: `m/44'/242'/0'/0'` for the first account.

**API:**

```go
type MnemonicType int // MnemonicBIP39, MnemonicLegacy, MnemonicUnknown

func TypeOf(phrase string) (MnemonicType, error)
func FromMnemonic(phrase, password string) (*PrivateKey, error) // BIP39 path, errors on Unknown/Legacy
func (k *PrivateKey) Mnemonic() (string, error)                 // export the 24 words
```

`FromMnemonic` refusing ambiguous and legacy phrases is deliberate: deriving the wrong branch silently hands the user an empty wallet and a support ticket. Callers who need legacy pass through an explicit `FromMnemonicType(phrase, password, MnemonicLegacy)`.

**Checks:** golden vectors — at least two known Nimiq phrase → address pairs from the Hub/Keyguard test fixtures, one wrong-checksum phrase, one with a passphrase, one ambiguous phrase asserting `MnemonicUnknown`. Round-trip `Mnemonic()` → `FromMnemonic()`.

**Skipped:** other wordlists (Nimiq only ships English), BIP32 paths beyond account 0 until someone needs multi-account.

### Task 3: `rpc.Client.Send` convenience

Kills the most-copied snippet in the docs, which currently hands people a literal validity start height (`README.md:51`).

**Files:**
- Modify: `rpc/client.go`
- Modify: `README.md`, `examples/basic/main.go`

```go
// Send builds, signs, and broadcasts a basic transfer, filling in the
// validity start height from the chain head and the fee from the network
// minimum. Returns the transaction hash.
func (c *Client) Send(ctx context.Context, s nimiq.Signer, to nimiq.Address, value nimiq.Luna) (string, error)
```

Composes existing pieces only: `BlockNumber` → `NewBasicTransaction` → `EstimateFee` → `SignTransaction` → `SendTransaction`. Network comes from `WithNetwork` on the client — required for `Send`, never read from the node (a node's answer is not authority over what the application meant to sign). Error clearly if unset: `rpc: Send requires WithNetwork`.

```go
// WithNetwork sets the network transactions are signed for. Required for
// Send; it is not read from the node, since a node's answer is not
// authority over what your application meant to sign.
func WithNetwork(n nimiq.NetworkID) Option
```

**Check:** `httptest` server asserting the broadcast transaction carries the fetched height and a fee ≥ the advertised minimum.

**Skipped:** a builder/options struct. Anything beyond a plain transfer builds the transaction itself and calls `SendTransaction`.

### Task 4: Cashlinks

Nimiq-specific, no Go implementation exists anywhere, and it is the payment primitive mini apps actually use.

**Files:**
- Create: `cashlink.go`, `cashlink_test.go`

**Spec** (from `nimiq/cashlink-generator/src/cashlink.ts`): URL is `<baseURL>#<payload>`, payload is base64url of

| Field | Size | Notes |
|---|---|---|
| private key | 32 | the funded throwaway account |
| value | 8 | big-endian u64 luna |
| message length | 1 | present only if message or theme is set |
| message | 0–255 | UTF-8 |
| theme | 1 | present only if non-zero |

No checksum. Nimiq's base64url uses `.` as the padding character and splits runs longer than 256 characters with `~`; both must be normalised on parse.

```go
type Cashlink struct {
	Key     *signer.PrivateKey
	Value   Luna
	Message string
	Theme   uint8
}

func ParseCashlink(url string) (*Cashlink, error)
func (c *Cashlink) URL(baseURL string) string
```

Creating and funding a cashlink is just a transfer to `AddressFromPublicKey(c.Key.Public())` — no helper needed; the doc comment says so.

**Check:** golden vector from a real hub.nimiq.com link (value + message + theme, and a bare one), plus a round-trip. Reject payloads with trailing bytes, as the HTLC parser does.

### Task 5: Vesting creation payload

The SDK parses HTLC creation data but not vesting, which is the sibling contract and what team/airdrop contracts use.

**Files:**
- Create: `vesting.go`, `vesting_test.go`

Mirror `ParseHTLCCreation` exactly:

```go
type VestingCreation struct {
	Owner      Address
	StartTime  uint64 // milliseconds, like HTLCCreation.Timeout
	TimeStep   uint64
	StepAmount Luna
	TotalAmount Luna
}

func ParseVestingCreation(data []byte) (*VestingCreation, error)
```

Payload is length-dependent in core-rs (`vesting_contract.rs`): the short form carries only owner + step, the full form all four fields. Handle both, reject anything else.

**Check:** one fixture per encoding length, one truncated, one with trailing bytes.

**Skipped:** vesting redemption helpers and a "currently vested" calculator, until a caller needs them.
